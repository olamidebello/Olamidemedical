Set up a development environment

Use Python 3.11 or later. Run python server.py --create-user administrator --role admin, then python server.py and open http://127.0.0.1:8080. Use synthetic records. There is no default password; choose at least 12 characters.

Architecture and data

server.py serves the browser and authenticated JSON API. SQLite stores hospital-scoped records. tenancy.py enforces hospital boundaries; registration.py and providers.py manage onboarding; ward.py handles charting and rosters; mobility.py controls sharing. Other modules cover devices, operations, safety, telehealth and AI. DATABASE_PATH selects the database; preserve its data and WAL files during recovery.

API and permissions

POST /api/login creates an HttpOnly session cookie. GET /api/me returns permitted modules and schemas. Module APIs support GET, POST and PATCH; PATCH requires the current version. Authenticated mutations require X-Requested-With: OlamideMedical. Derive hospital and actor from the authenticated session. Validate every linked record against the same hospital and patient. Never trust a browser-supplied role or tenant ID.

Clinical changes

Keep signed records immutable. Record corrections as linked additions with a reason, author and time. Use version checks to prevent lost updates. Add isolation and denial tests when changing permissions. Platform administration does not grant global clinical access.

Verification

Run python -m unittest discover -s tests -v and node --check static/app.js. In tests/browser run npm ci and npm test. Syntax-check ansible/deploy-multitenant.yml before deployment. Exercise both successful workflows and cross-hospital denials.

Deploy and recover

Use ansible/deploy-multitenant.yml with an explicitly selected reviewed medical_revision. The playbook tests source, pauses services, backs up source/data, migrates, installs and checks health. Test restoration separately; a health response does not validate every clinical workflow. Keep HTTPS reverse proxy and certificates configured. Never overwrite local source changes with force.

Secrets and integrations

Keep OPENAI_API_KEY in protected server configuration, never Git, browser JavaScript or logs. AI is disabled per hospital until enabled and configured; submit de-identified questions only. Device feeds enter a review queue. Telemedicine requires consent, browser permissions and tested network/TURN configuration. Do not claim universal device, payer or external EHR compatibility.

Further reference

Repository documents docs/TENANCY_AND_INTEGRATIONS.md and docs/CHARTING_AND_ROSTERS.md describe detailed behavior and deployment limits. This is a single-instance evaluation foundation requiring independent security and clinical validation before real patient use.
